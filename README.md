# 网页工具库-Web Tools Library

一个由 AI 生成、集中管理的网页工具库。使用原生 HTML、CSS 和 JavaScript 构建，无需安装依赖，适合本地运行、收藏整理和二次开发。

这个项目的灵感来源于 AI 制作的 HTML 网页工具：它们通常开箱即用、界面美观，但容易散落在不同文件夹中。Web Tools Library 希望把你手头收藏的 HTML 工具放到同一个页面下，形成一个属于自己的本地工具箱。

后续新增工具仍然可以完全由 AI 生成。项目的 `help.html` 提供了详细的新增工具教程，只需要简单修改首页 `index.html` 中的配置，就能把新工具接入统一入口。懂不懂代码都能上手，也可以直接让 AI 工具帮你修改代码。

## 特点-Features

* **Standalone HTML tools**：每个工具都是独立的 HTML 文件，复制、分享、备份都很方便。
* **Category navigation**：通过分类快速查找工具。
* **Search**：支持搜索工具名称、简介和分类。
* **Easy to extend**：新增工具通常只需要修改首页 `index.html` 的配置。
* **AI-friendly**：提供提示词模板，可让 AI 生成新工具；也可以让 AI 帮你把工具加入首页。
* **Beginner-friendly**：帮助文件提供详细教程，不熟悉代码也能照着操作。
* **Local-first**：工具默认在浏览器本地运行，不依赖后端服务。
* **No dependencies**：无需安装依赖，打开 `index.html` 即可使用。

## 开始-Getting Started

1. 下载或克隆本仓库。
2. 打开 `index.html`。
3. 通过分类栏或搜索框查找工具。
4. 点击工具卡片进入对应页面。
5. 想新增工具时，查看 `help.html` 中的详细教程。

部分工具可能受浏览器安全策略限制，具体要求请查看对应工具页面说明。

## 用AI新增工具-Use AI to Create a New Tool

1. 在 `tools/` 目录下新增一个独立的 HTML 文件。
2. 打开 `index.html`，在 `tools` 数组中仿照已有条目增加对应配置。
3. 如需新分类，在 `categories` 数组中添加分类名称。
4. 确保工具配置中的 `category` 与分类名称完全一致。
5. 保存后，在浏览器中打开 `index.html`，测试工具链接和功能。
6. 如果你不想手动改代码，可以把 `index.html` 和 `help.html` 一起发给 AI，让 AI 帮你把新工具加入首页。

### 新增示例-Add tool Example

#### 步骤1：修改首页文件 index.html

**新增工具**

```html
{
  name: "CSV 转 JSON",
  category: "数据处理",
  icon: "🔄",
  description: "将 CSV 表格文本转换为 JSON 数据。",
  href: "tools/csv-to-json.html"
}
```

字段说明：

- `name`：首页显示的工具名称。
- `category`：该工具所属分类，必须与分类列表中的名称完全一致。
- `icon`：卡片图标，可以使用 Emoji。
- `description`：首页卡片的简短说明。
- `href`：工具页面的相对路径，文件名必须完全匹配。

```text
注意 JavaScript 语法：数组中相邻的对象之间需要逗号，最后一项末尾的逗号通常可以省略。不要把新对象放在数组外面。
```


**新增分类**

打开 `index.html`，找到 `const categories = [ ... ]`，添加分类名称即可。例如：

```html
const categories = [
  "文本处理",
  "数据处理",
  "开发辅助",
  "文件工具",
  "图像处理",
  "视频工具"
];
```
之后在新工具配置中使用完全相同的分类名称：
```html
{
  name: "视频信息查看",
  category: "视频工具",
  icon: "🎬",
  description: "查看视频文件的基本信息。",
  href: "tools/video-info.html"
}
```
分类按钮会自动生成，不需要手动编写按钮 HTML。新增分类后，至少要有一个工具的 category 使用该名称，筛选该分类时才会看到工具。


#### 步骤2：AI生成需要的工具

**格式要求**

每次让 AI 生成工具时，先发送以下“格式要求”，再发送下一节的“功能要求”。这能尽量保持所有工具页面风格一致。

```text
请为我的「网页工具库」生成一个独立的工具 HTML 页面，并严格遵守以下要求：

1. 文件与技术要求
- 只生成一个完整、可独立运行的 HTML 文件。
- 使用原生 HTML、CSS、JavaScript，不使用 React、Vue 等框架。
- 不依赖后端、数据库、Node.js、构建工具、第三方 CDN 或外部网络资源。
- 所有必要代码都写在同一个 HTML 文件中。
- 支持 Windows 和 Linux 上的常见现代浏览器，优先支持本地直接打开。
- 如果浏览器安全限制导致某项功能无法在 file:// 下使用，必须明确说明并优先提供不依赖服务器的实现。

2. 页面布局
- 页面顶部必须显示标题「网页工具库」。
- 页面顶部左上角或导航区域必须有明显的「首页」按钮。
- 点击「首页」跳转到 ../index.html，因为工具文件统一放在 tools 文件夹中。
- 内容区展示工具名称、操作区、结果区和必要说明。
- 使用简洁、清晰、现代的工具型界面：浅色背景、白色卡片、蓝色强调色、适度圆角和留白。
- 使用系统字体，保证中文正常显示；适配电脑和手机屏幕。
- 输入、输出、按钮、提示和错误信息应清晰区分。

3. 交互要求
- 所有按钮必须实现真实功能，不得只有界面没有逻辑。
- 输入、处理、结果展示的流程必须清晰。
- 实现合理的输入校验、异常处理、边界值处理和操作反馈。
- 涉及复制、下载、导入或导出时，按功能要求实现；不要添加无意义按钮。
- 受到浏览器权限、file:// 安全策略或本地资源限制的功能，必须明确说明，不能假装已经实现。

4. 代码质量与安全
- 代码结构清楚，变量和函数命名有意义，关键逻辑添加必要的中文注释。
- 处理空输入、非法输入、边界值和异常情况。
- 不使用 eval 执行用户输入，不将用户输入直接拼接为不安全的 HTML。
- 不上传用户数据，不调用外部接口，除非功能要求明确提出。
- 不得虚构处理结果，不留下未实现的核心功能、TODO 或伪代码。
- 避免无必要的复杂封装，优先保证可维护、可调试。

5. 输出要求
- 先给出建议的英文文件名，例如 csv-to-json.html。
- 然后提供完整 HTML 源代码，不得省略代码或用“其余代码同上”代替。
- 简要说明保存文件的目录和测试方法。
- 除非我明确要求，否则不要修改首页 index.html，不要要求我重写整个工具库。
- 若有无法在纯本地 HTML 环境实现的功能，必须指出原因和替代方案。

请严格遵守上述要求，并在此基础上实现我接下来描述的具体功能。
```
